# 用戶通訊模組 - 角色互換改造方案

## 📋 文檔資訊

- **方案名稱**: 去角色化對話設計 (Role-Agnostic Conversation Design)
- **版本**: 2.0
- **建立日期**: 2025-11-09
- **目標**: 支援買家/賣家角色互換時仍使用同一對話室

---

## 🎯 問題分析

### 當前設計的限制

```
場景：
1. 用戶 A 發布商品 X → 用戶 B 詢問 → 建立對話 1 (A=seller, B=buyer, item=X)
2. 用戶 B 發布商品 Y → 用戶 A 詢問 → 建立對話 2 (B=seller, A=buyer, item=Y)

結果：
- 用戶 A 和 B 之間有 2 個獨立的對話室
- UI 界面分散，用戶體驗不佳
- 訊息歷史被割裂
```

### 期望的設計

```
場景：
1. 用戶 A 和 B 首次互動 → 建立唯一對話室
2. 在同一對話室中可以討論：
   - A 發布的商品 X
   - B 發布的商品 Y
   - 未來的其他商品
   
結果：
- 用戶 A 和 B 之間只有 1 個統一的對話室
- 所有訊息集中管理
- 更符合真實世界的對話邏輯
```

## 📐 方案一：去角色化設計（推薦）

### 核心概念

- **對話室不再綁定固定角色**，改為綁定兩個用戶
- **訊息可關聯到具體商品**，支援一個對話討論多個商品
- **角色動態判斷**，基於討論的商品來決定誰是賣家/買家

### 資料表結構改造

#### 1. `conversations` 表（新結構）

```sql
CREATE TABLE public.conversations (
    -- 主鍵
    id BIGSERIAL PRIMARY KEY,
    
    -- 參與者（去角色化）
    participant_1_id UUID NOT NULL,
    participant_2_id UUID NOT NULL,
    
    -- 主要討論的商品（可選，向後相容）
    primary_item_id BIGINT,
    
    -- 軟刪除（雙向獨立）
    deleted_by_participant_1 BOOLEAN NOT NULL DEFAULT false,
    deleted_by_participant_2 BOOLEAN NOT NULL DEFAULT false,
    participant_1_deleted_at TIMESTAMPTZ,
    participant_2_deleted_at TIMESTAMPTZ,
    
    -- 時間戳記
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    
    -- 約束條件
    CONSTRAINT fk_participant_1 
        FOREIGN KEY (participant_1_id) 
        REFERENCES public.users(id) ON DELETE CASCADE,
    
    CONSTRAINT fk_participant_2 
        FOREIGN KEY (participant_2_id) 
        REFERENCES public.users(id) ON DELETE CASCADE,
    
    CONSTRAINT fk_primary_item 
        FOREIGN KEY (primary_item_id) 
        REFERENCES public.items(id) ON DELETE SET NULL,
    
    -- 確保 participant_1 的 ID 總是小於 participant_2（標準化）
    CONSTRAINT check_participant_order 
        CHECK (participant_1_id < participant_2_id),
    
    -- 確保不會自己跟自己對話
    CONSTRAINT check_different_participants 
        CHECK (participant_1_id != participant_2_id),
    
    -- 唯一性：兩個用戶之間只能有一個對話室
    CONSTRAINT unique_conversation 
        UNIQUE (participant_1_id, participant_2_id)
);
```

**關鍵設計點**：

1. **標準化排序**：`participant_1_id < participant_2_id`
   - 避免 (A, B) 和 (B, A) 被視為不同對話
   - 簡化查詢邏輯

2. **主要商品為可選**：`primary_item_id` 可為 NULL
   - 支援純聊天（不討論特定商品）
   - 對話可以討論多個商品

3. **雙向軟刪除**：保持獨立的刪除標記
   - 用戶可各自刪除對話，互不影響

#### 2. `conversation_messages` 表（新結構）

```sql
CREATE TABLE public.conversation_messages (
    -- 主鍵
    id BIGSERIAL PRIMARY KEY,
    
    -- 所屬對話
    conversation_id BIGINT NOT NULL,
    
    -- 發送者
    sender_id UUID NOT NULL,
    
    -- 訊息內容
    content TEXT NOT NULL,
    
    -- 關聯商品（可選）
    related_item_id BIGINT,
    
    -- 訊息類型（擴展性）
    message_type VARCHAR(20) NOT NULL DEFAULT 'text'
        CHECK (message_type IN ('text', 'image', 'item_reference', 'system')),
    
    -- 已讀狀態
    is_read BOOLEAN NOT NULL DEFAULT false,
    read_at TIMESTAMPTZ,
    
    -- 軟刪除（雙向獨立）
    deleted_by_sender BOOLEAN NOT NULL DEFAULT false,
    deleted_by_receiver BOOLEAN NOT NULL DEFAULT false,
    sender_deleted_at TIMESTAMPTZ,
    receiver_deleted_at TIMESTAMPTZ,
    
    -- 時間戳記
    sent_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    
    -- 約束條件
    CONSTRAINT fk_conversation 
        FOREIGN KEY (conversation_id) 
        REFERENCES public.conversations(id) ON DELETE CASCADE,
    
    CONSTRAINT fk_sender 
        FOREIGN KEY (sender_id) 
        REFERENCES public.users(id) ON DELETE CASCADE,
    
    CONSTRAINT fk_related_item 
        FOREIGN KEY (related_item_id) 
        REFERENCES public.items(id) ON DELETE SET NULL
);
```

**新增欄位說明**：

- **`related_item_id`**: 標記此訊息討論的是哪個商品
  - 用於在 UI 中顯示商品卡片
  - 支援在同一對話中討論多個商品

- **`message_type`**: 訊息類型
  - `text`: 純文字訊息
  - `image`: 圖片訊息
  - `item_reference`: 商品引用
  - `system`: 系統訊息（如交易完成通知）

### 索引設計

```sql
-- ===== conversations 表索引 =====

-- 1. 參與者查詢索引
CREATE INDEX idx_conversations_participant_1 
ON public.conversations(participant_1_id);

CREATE INDEX idx_conversations_participant_2 
ON public.conversations(participant_2_id);

-- 2. 複合索引：參與者 + 更新時間（優化對話列表查詢）
CREATE INDEX idx_conversations_p1_updated 
ON public.conversations(participant_1_id, updated_at DESC) 
WHERE NOT deleted_by_participant_1;

CREATE INDEX idx_conversations_p2_updated 
ON public.conversations(participant_2_id, updated_at DESC) 
WHERE NOT deleted_by_participant_2;

-- 3. 主要商品索引（向後相容）
CREATE INDEX idx_conversations_primary_item 
ON public.conversations(primary_item_id) 
WHERE primary_item_id IS NOT NULL;

-- ===== conversation_messages 表索引 =====

-- 1. 對話訊息索引
CREATE INDEX idx_messages_conversation 
ON public.conversation_messages(conversation_id, sent_at DESC);

-- 2. 關聯商品索引
CREATE INDEX idx_messages_related_item 
ON public.conversation_messages(related_item_id) 
WHERE related_item_id IS NOT NULL;

-- 3. 未讀訊息索引
CREATE INDEX idx_messages_unread 
ON public.conversation_messages(conversation_id, sender_id, is_read) 
WHERE NOT is_read;

-- 4. 訊息類型索引（用於篩選特定類型訊息）
CREATE INDEX idx_messages_type 
ON public.conversation_messages(conversation_id, message_type);
```

### 核心 RPC 函數

#### 1. 建立或取得對話（新版）

```sql
CREATE OR REPLACE FUNCTION create_or_get_conversation_v2(
    p_other_user_id UUID,
    p_item_id BIGINT DEFAULT NULL
)
RETURNS TABLE(
    conversation_id BIGINT,
    participant_1_id UUID,
    participant_2_id UUID,
    primary_item_id BIGINT,
    is_new BOOLEAN
) 
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
    v_current_user_id UUID := auth.uid();
    v_p1_id UUID;
    v_p2_id UUID;
    v_existing_conversation RECORD;
    v_is_new BOOLEAN := false;
BEGIN
    -- 驗證用戶已登入
    IF v_current_user_id IS NULL THEN
        RAISE EXCEPTION '需要登入才能建立對話';
    END IF;
    
    -- 驗證不能跟自己對話
    IF v_current_user_id = p_other_user_id THEN
        RAISE EXCEPTION '無法與自己建立對話';
    END IF;
    
    -- 驗證對方用戶存在
    IF NOT EXISTS (SELECT 1 FROM users WHERE id = p_other_user_id) THEN
        RAISE EXCEPTION '對方用戶不存在';
    END IF;
    
    -- 如果指定了商品，驗證商品存在
    IF p_item_id IS NOT NULL THEN
        IF NOT EXISTS (SELECT 1 FROM items WHERE id = p_item_id) THEN
            RAISE EXCEPTION '商品不存在';
        END IF;
    END IF;
    
    -- 標準化參與者順序（較小的 UUID 為 participant_1）
    IF v_current_user_id < p_other_user_id THEN
        v_p1_id := v_current_user_id;
        v_p2_id := p_other_user_id;
    ELSE
        v_p1_id := p_other_user_id;
        v_p2_id := v_current_user_id;
    END IF;
    
    -- 查詢是否已存在對話
    SELECT * INTO v_existing_conversation
    FROM conversations
    WHERE participant_1_id = v_p1_id 
      AND participant_2_id = v_p2_id;
    
    IF FOUND THEN
        -- 對話已存在
        
        -- 如果對話被當前用戶軟刪除，則恢復
        IF (v_current_user_id = v_p1_id AND v_existing_conversation.deleted_by_participant_1) OR
           (v_current_user_id = v_p2_id AND v_existing_conversation.deleted_by_participant_2) THEN
            UPDATE conversations
            SET 
                deleted_by_participant_1 = CASE 
                    WHEN v_current_user_id = v_p1_id THEN false 
                    ELSE deleted_by_participant_1 
                END,
                deleted_by_participant_2 = CASE 
                    WHEN v_current_user_id = v_p2_id THEN false 
                    ELSE deleted_by_participant_2 
                END,
                participant_1_deleted_at = CASE 
                    WHEN v_current_user_id = v_p1_id THEN NULL 
                    ELSE participant_1_deleted_at 
                END,
                participant_2_deleted_at = CASE 
                    WHEN v_current_user_id = v_p2_id THEN NULL 
                    ELSE participant_2_deleted_at 
                END,
                updated_at = now()
            WHERE id = v_existing_conversation.id;
        END IF;
        
        -- 如果指定了新商品且對話尚未設定主要商品，則設定
        IF p_item_id IS NOT NULL AND v_existing_conversation.primary_item_id IS NULL THEN
            UPDATE conversations
            SET primary_item_id = p_item_id,
                updated_at = now()
            WHERE id = v_existing_conversation.id;
        END IF;
        
        v_is_new := false;
    ELSE
        -- 建立新對話
        INSERT INTO conversations (
            participant_1_id, 
            participant_2_id, 
            primary_item_id
        )
        VALUES (
            v_p1_id, 
            v_p2_id, 
            p_item_id
        )
        RETURNING id INTO v_existing_conversation;
        
        v_is_new := true;
    END IF;
    
    -- 返回對話資訊
    RETURN QUERY
    SELECT 
        c.id,
        c.participant_1_id,
        c.participant_2_id,
        c.primary_item_id,
        v_is_new
    FROM conversations c
    WHERE c.id = v_existing_conversation.id;
END;
$$;
```

#### 2. 查詢用戶對話列表（新版）

```sql
CREATE OR REPLACE FUNCTION get_user_conversations_v2(
    p_page INTEGER DEFAULT 1,
    p_size INTEGER DEFAULT 20,
    p_include_deleted BOOLEAN DEFAULT false
)
RETURNS TABLE(
    conversation_id BIGINT,
    other_user_id UUID,
    other_user_nickname VARCHAR(50),
    other_user_avatar TEXT,
    primary_item_id BIGINT,
    primary_item_title VARCHAR(50),
    primary_item_image TEXT,
    latest_message TEXT,
    latest_message_time TIMESTAMPTZ,
    latest_message_sender_id UUID,
    unread_count BIGINT,
    conversation_created_at TIMESTAMPTZ,
    conversation_updated_at TIMESTAMPTZ
)
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
    v_current_user_id UUID := auth.uid();
    v_offset INTEGER := (p_page - 1) * p_size;
BEGIN
    RETURN QUERY
    WITH user_conversations AS (
        SELECT 
            c.id,
            c.participant_1_id,
            c.participant_2_id,
            c.primary_item_id,
            c.created_at,
            c.updated_at,
            -- 判斷對方是誰
            CASE 
                WHEN c.participant_1_id = v_current_user_id THEN c.participant_2_id
                ELSE c.participant_1_id
            END AS other_user,
            -- 判斷是否被當前用戶刪除
            CASE 
                WHEN c.participant_1_id = v_current_user_id THEN c.deleted_by_participant_1
                ELSE c.deleted_by_participant_2
            END AS is_deleted
        FROM conversations c
        WHERE c.participant_1_id = v_current_user_id 
           OR c.participant_2_id = v_current_user_id
    ),
    latest_messages AS (
        SELECT DISTINCT ON (cm.conversation_id)
            cm.conversation_id,
            cm.content,
            cm.sent_at,
            cm.sender_id
        FROM conversation_messages cm
        WHERE cm.conversation_id IN (SELECT id FROM user_conversations)
        ORDER BY cm.conversation_id, cm.sent_at DESC
    ),
    unread_counts AS (
        SELECT 
            cm.conversation_id,
            COUNT(*) AS count
        FROM conversation_messages cm
        WHERE cm.conversation_id IN (SELECT id FROM user_conversations)
          AND cm.sender_id != v_current_user_id
          AND cm.is_read = false
        GROUP BY cm.conversation_id
    )
    SELECT 
        uc.id,
        uc.other_user,
        u.nickname,
        u.profile_picture_url,
        uc.primary_item_id,
        i.title,
        CASE 
            WHEN i.image_urls IS NOT NULL AND array_length(i.image_urls, 1) > 0 
            THEN i.image_urls[1]
            ELSE NULL
        END,
        lm.content,
        lm.sent_at,
        lm.sender_id,
        COALESCE(urc.count, 0),
        uc.created_at,
        uc.updated_at
    FROM user_conversations uc
    LEFT JOIN users u ON u.id = uc.other_user
    LEFT JOIN items i ON i.id = uc.primary_item_id
    LEFT JOIN latest_messages lm ON lm.conversation_id = uc.id
    LEFT JOIN unread_counts urc ON urc.conversation_id = uc.id
    WHERE p_include_deleted OR NOT uc.is_deleted
    ORDER BY uc.updated_at DESC
    LIMIT p_size
    OFFSET v_offset;
END;
$$;
```

#### 3. 發送訊息（新版）

```sql
CREATE OR REPLACE FUNCTION send_message_v2(
    p_conversation_id BIGINT,
    p_content TEXT,
    p_related_item_id BIGINT DEFAULT NULL,
    p_message_type VARCHAR(20) DEFAULT 'text'
)
RETURNS TABLE(
    message_id BIGINT,
    conversation_id BIGINT,
    sender_id UUID,
    content TEXT,
    related_item_id BIGINT,
    message_type VARCHAR(20),
    sent_at TIMESTAMPTZ
)
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
    v_current_user_id UUID := auth.uid();
    v_conversation RECORD;
    v_new_message_id BIGINT;
BEGIN
    -- 驗證對話存在且用戶有權限
    SELECT * INTO v_conversation
    FROM conversations
    WHERE id = p_conversation_id
      AND (participant_1_id = v_current_user_id OR participant_2_id = v_current_user_id);
    
    IF NOT FOUND THEN
        RAISE EXCEPTION '對話不存在或無權限存取';
    END IF;
    
    -- 驗證訊息內容不為空
    IF p_content IS NULL OR trim(p_content) = '' THEN
        RAISE EXCEPTION '訊息內容不能為空';
    END IF;
    
    -- 驗證訊息類型
    IF p_message_type NOT IN ('text', 'image', 'item_reference', 'system') THEN
        RAISE EXCEPTION '無效的訊息類型';
    END IF;
    
    -- 如果指定了關聯商品，驗證商品存在
    IF p_related_item_id IS NOT NULL THEN
        IF NOT EXISTS (SELECT 1 FROM items WHERE id = p_related_item_id) THEN
            RAISE EXCEPTION '關聯商品不存在';
        END IF;
    END IF;
    
    -- 插入新訊息
    INSERT INTO conversation_messages (
        conversation_id,
        sender_id,
        content,
        related_item_id,
        message_type
    )
    VALUES (
        p_conversation_id,
        v_current_user_id,
        p_content,
        p_related_item_id,
        p_message_type
    )
    RETURNING id INTO v_new_message_id;
    
    -- 更新對話的 updated_at（觸發器會自動處理）
    UPDATE conversations
    SET updated_at = now()
    WHERE id = p_conversation_id;
    
    -- 返回新訊息
    RETURN QUERY
    SELECT 
        cm.id,
        cm.conversation_id,
        cm.sender_id,
        cm.content,
        cm.related_item_id,
        cm.message_type,
        cm.sent_at
    FROM conversation_messages cm
    WHERE cm.id = v_new_message_id;
END;
$$;
```

#### 4. 輔助函數：取得對話中討論的所有商品

```sql
CREATE OR REPLACE FUNCTION get_conversation_items(
    p_conversation_id BIGINT
)
RETURNS TABLE(
    item_id BIGINT,
    item_title VARCHAR(50),
    item_image TEXT,
    item_price INTEGER,
    seller_id UUID,
    seller_nickname VARCHAR(50),
    message_count BIGINT,
    first_mentioned_at TIMESTAMPTZ,
    last_mentioned_at TIMESTAMPTZ
)
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
    v_current_user_id UUID := auth.uid();
BEGIN
    -- 驗證用戶有權限查看此對話
    IF NOT EXISTS (
        SELECT 1 FROM conversations
        WHERE id = p_conversation_id
          AND (participant_1_id = v_current_user_id OR participant_2_id = v_current_user_id)
    ) THEN
        RAISE EXCEPTION '對話不存在或無權限存取';
    END IF;
    
    RETURN QUERY
    WITH conversation_items AS (
        -- 從對話的主要商品
        SELECT 
            c.primary_item_id AS item_id,
            MIN(c.created_at) AS first_mentioned,
            MAX(c.updated_at) AS last_mentioned,
            0::BIGINT AS msg_count
        FROM conversations c
        WHERE c.id = p_conversation_id
          AND c.primary_item_id IS NOT NULL
        
        UNION ALL
        
        -- 從訊息中的關聯商品
        SELECT 
            cm.related_item_id AS item_id,
            MIN(cm.sent_at) AS first_mentioned,
            MAX(cm.sent_at) AS last_mentioned,
            COUNT(*) AS msg_count
        FROM conversation_messages cm
        WHERE cm.conversation_id = p_conversation_id
          AND cm.related_item_id IS NOT NULL
        GROUP BY cm.related_item_id
    )
    SELECT 
        i.id,
        i.title,
        CASE 
            WHEN i.image_urls IS NOT NULL AND array_length(i.image_urls, 1) > 0 
            THEN i.image_urls[1]
            ELSE NULL
        END,
        i.price,
        i.user_id,
        u.nickname,
        SUM(ci.msg_count),
        MIN(ci.first_mentioned),
        MAX(ci.last_mentioned)
    FROM conversation_items ci
    JOIN items i ON i.id = ci.item_id
    JOIN users u ON u.id = i.user_id
    GROUP BY i.id, i.title, i.image_urls, i.price, i.user_id, u.nickname
    ORDER BY MAX(ci.last_mentioned) DESC;
END;
$$;
```

### RLS 安全性策略

```sql
-- ===== conversations 表 RLS =====

ALTER TABLE public.conversations ENABLE ROW LEVEL SECURITY;

-- 查看：用戶可以查看自己參與的對話
CREATE POLICY "Users can view their conversations"
ON public.conversations
FOR SELECT
USING (
    auth.uid() = participant_1_id OR auth.uid() = participant_2_id
);

-- 插入：用戶可以建立自己參與的對話
CREATE POLICY "Users can create their conversations"
ON public.conversations
FOR INSERT
WITH CHECK (
    auth.uid() = participant_1_id OR auth.uid() = participant_2_id
);

-- 更新：用戶可以更新自己參與的對話
CREATE POLICY "Users can update their conversations"
ON public.conversations
FOR UPDATE
USING (
    auth.uid() = participant_1_id OR auth.uid() = participant_2_id
)
WITH CHECK (
    auth.uid() = participant_1_id OR auth.uid() = participant_2_id
);

-- 刪除：用戶可以刪除自己參與的對話
CREATE POLICY "Users can delete their conversations"
ON public.conversations
FOR DELETE
USING (
    auth.uid() = participant_1_id OR auth.uid() = participant_2_id
);

-- ===== conversation_messages 表 RLS =====

ALTER TABLE public.conversation_messages ENABLE ROW LEVEL SECURITY;

-- 查看：用戶可以查看所屬對話的訊息
CREATE POLICY "Users can view messages in their conversations"
ON public.conversation_messages
FOR SELECT
USING (

ON public.conversation_messages
FOR INSERT
WITH CHECK (
    sender_id = auth.uid()

          AND (participant_1_id = auth.uid() OR participant_2_id = auth.uid())
    )
);

CREATE POLICY "Users can update messages"
ON public.conversation_messages
FOR UPDATE
USING (
    EXISTS (
        SELECT 1 FROM conversations
        WHERE id = conversation_id
```

### Step 3: 資料遷移

```sql
-- 遷移對話資料
INSERT INTO conversations_v2 (
    participant_1_id,
    participant_2_id,
    primary_item_id,
    deleted_by_participant_1,
    deleted_by_participant_2,
    participant_1_deleted_at,
    participant_2_deleted_at,
    created_at,
    updated_at
)
SELECT 
    LEAST(buyer_id, seller_id) AS participant_1_id,
    GREATEST(buyer_id, seller_id) AS participant_2_id,
    item_id AS primary_item_id,
    deleted_by_buyer AS deleted_by_participant_1,
    deleted_by_seller AS deleted_by_participant_2,
    buyer_deleted_at AS participant_1_deleted_at,
    seller_deleted_at AS participant_2_deleted_at,
    created_at,
    updated_at
FROM conversations_backup;

-- 遷移訊息資料
INSERT INTO conversation_messages_v2 (
    conversation_id,
    sender_id,
    content,
    related_item_id,
    message_type,
    is_read,
    read_at,
    deleted_by_sender,
    deleted_by_receiver,
    sender_deleted_at,
    receiver_deleted_at,
    sent_at
)
SELECT 
    c_new.id AS conversation_id,
    cm.sender_id,
    cm.content,
    c_old.item_id AS related_item_id, -- 將原本的對話商品作為關聯商品
    'text' AS message_type,
    cm.is_read,
    NULL AS read_at,
    cm.deleted_by_sender,
    cm.deleted_by_receiver,
    cm.sender_deleted_at,
    cm.receiver_deleted_at,
    cm.sent_at
FROM conversation_messages_backup cm
JOIN conversations_backup c_old ON c_old.id = cm.conversation_id
JOIN conversations_v2 c_new ON 
    c_new.participant_1_id = LEAST(c_old.buyer_id, c_old.seller_id)
    AND c_new.participant_2_id = GREATEST(c_old.buyer_id, c_old.seller_id);
```

```sql
-- 處理用戶 A 和 B 之間可能存在的多個對話（因角色互換產生）
WITH duplicate_conversations AS (

        participant_1_id,
        participant_2_id,
        array_agg(id ORDER BY created_at) AS conversation_ids,
        COUNT(*) AS conversation_count
    FROM conversations_v2
    GROUP BY participant_1_id, participant_2_id
    HAVING COUNT(*) > 1

SELECT * FROM duplicate_conversations;
```

```sql
    cm_old.id,
    cm_old.conversation_id AS old_conversation_id,
    c_old.buyer_id,
    c_old.seller_id
FROM conversation_messages_old cm_old
JOIN conversations_old c_old ON c_old.id = cm_old.conversation_id

    SELECT 1
```

## ✅ 優點與缺點

### 優點

✅ **解決核心問題**: 角色互換時仍使用同一對話室  
✅ **更符合直覺**: 兩個用戶之間只有一個對話  
✅ **減少資料重複**: 不會產生多個對話室  
✅ **支援多商品討論**: 在同一對話中討論多個商品  
✅ **擴展性強**: 易於添加新功能（如群組對話）  

### 缺點

❌ **遷移複雜度高**: 需要遷移現有資料  
❌ **破壞性變更**: 需要更新所有前端代碼  
❌ **向後不相容**: 舊版 API 無法使用  
❌ **學習成本**: 開發者需要理解新設計

```sql
-- migration_to_v2.sql
-- 完整的資料遷移腳本

BEGIN;

-- Step 1: 建立新資料表
-- （省略，使用前面定義的結構）

-- Step 2: 遷移資料
-- （省略，使用前面的遷移 SQL）

-- Step 3: 處理重複對話
DO $$
DECLARE
    dup_record RECORD;
    keep_conversation_id BIGINT;
BEGIN
    FOR dup_record IN 
        SELECT 
            participant_1_id,
            participant_2_id,
            array_agg(id ORDER BY created_at) AS conversation_ids
        FROM conversations_v2
        GROUP BY participant_1_id, participant_2_id
        HAVING COUNT(*) > 1
    LOOP
        -- 保留最早的對話
        keep_conversation_id := dup_record.conversation_ids[1];
        
        -- 將其他對話的訊息遷移到保留的對話
        UPDATE conversation_messages_v2
        SET conversation_id = keep_conversation_id
        WHERE conversation_id = ANY(dup_record.conversation_ids[2:]);
        
        -- 刪除重複的對話
        DELETE FROM conversations_v2
        WHERE id = ANY(dup_record.conversation_ids[2:]);
        
        RAISE NOTICE '合併對話: % 和 % 之間的重複對話', 
            dup_record.participant_1_id, 
            dup_record.participant_2_id;
    END LOOP;
END $$;

-- Step 4: 驗證
DO $$
DECLARE
    old_count INTEGER;
    new_count INTEGER;
BEGIN
    SELECT COUNT(*) INTO old_count FROM conversations_old;
    SELECT COUNT(*) INTO new_count FROM conversations_v2;
    
    RAISE NOTICE '原有對話數: %, 新對話數: %', old_count, new_count;
END $$;

COMMIT;
```
