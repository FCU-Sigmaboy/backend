## 模組概述

### 🎯 功能目標

用戶通訊模組提供買賣雙方針對特定商品進行即時溝通的功能,支援:

- **對話管理**: 自動建立與管理買賣雙方的對話室
- **訊息傳遞**: 支援文字訊息的發送與接收
- **已讀狀態**: 追蹤訊息的已讀/未讀狀態
- **即時通訊**: 透過 Supabase Realtime 實現即時訊息推送
- **軟刪除機制**: 支援對話與訊息的軟刪除,保留歷史記錄
- **角色區分**: 區分買家(buyer)與賣家(seller)角色

### 🏗️ 設計原則

1. **唯一性保證**: 每個商品的買賣雙方僅能有一個對話室
2. **安全性優先**: 透過 RLS 確保用戶只能存取自己相關的對話
3. **效能優化**: 合理的索引設計與分頁查詢機制
4. **資料完整性**: 外鍵約束確保資料一致性
5. **擴展性**: 支援未來功能擴展(如多媒體訊息、訊息撤回等)

## 資料表結構

### 📊 1. `conversations` (對話表)

儲存買賣雙方針對特定商品的對話室資訊。

#### 欄位定義

| 欄位名稱 | 資料型別 | 約束條件 | 說明 |
|---------|---------|---------|------|
| `id` | `BIGSERIAL` | `PRIMARY KEY` | 對話唯一識別碼 (自動遞增) |
| `item_id` | `BIGINT` | `NOT NULL`, `FK` | 關聯的商品 ID |
| `buyer_id` | `UUID` | `NOT NULL`, `FK` | 買家用戶 ID |
| `seller_id` | `UUID` | `NOT NULL`, `FK` | 賣家用戶 ID |
| `deleted_by_buyer` | `BOOLEAN` | `DEFAULT false` | 買家是否已刪除此對話 |
| `deleted_by_seller` | `BOOLEAN` | `DEFAULT false` | 賣家是否已刪除此對話 |
| `buyer_deleted_at` | `TIMESTAMPTZ` | `NULL` | 買家刪除時間 |
| `seller_deleted_at` | `TIMESTAMPTZ` | `NULL` | 賣家刪除時間 |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL`, `DEFAULT now()` | 對話建立時間 |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL`, `DEFAULT now()` | 對話最後更新時間 |

#### 約束條件

```sql
-- 唯一性約束:每個商品的買賣雙方只能有一個對話室
UNIQUE(item_id, buyer_id, seller_id)

-- 外鍵約束
FOREIGN KEY (item_id) REFERENCES public.items(id) ON DELETE CASCADE
FOREIGN KEY (buyer_id) REFERENCES public.users(id) ON DELETE CASCADE
FOREIGN KEY (seller_id) REFERENCES public.users(id) ON DELETE CASCADE
```

#### 資料表說明

- **唯一性保證**: 透過複合唯一鍵 `(item_id, buyer_id, seller_id)` 確保同一商品的買賣雙方只有一個對話室
- **軟刪除支援**: 使用 `deleted_by_buyer` 和 `deleted_by_seller` 欄位實現雙向軟刪除
- **級聯刪除**: 當商品或用戶被刪除時,相關對話也會被刪除

---

### 📊 2. `conversation_messages` (訊息表)

儲存對話室中的所有訊息記錄。

#### 欄位定義

| 欄位名稱 | 資料型別 | 約束條件 | 說明 |
|---------|---------|---------|------|
| `id` | `BIGSERIAL` | `PRIMARY KEY` | 訊息唯一識別碼 (自動遞增) |
| `conversation_id` | `BIGINT` | `NOT NULL`, `FK` | 所屬對話室 ID |
| `sender_id` | `UUID` | `NOT NULL`, `FK` | 發送者用戶 ID |
| `content` | `TEXT` | `NOT NULL` | 訊息內容 |
| `is_read` | `BOOLEAN` | `NOT NULL`, `DEFAULT false` | 是否已讀 |
| `deleted_by_sender` | `BOOLEAN` | `DEFAULT false` | 發送者是否已刪除 |
| `deleted_by_receiver` | `BOOLEAN` | `DEFAULT false` | 接收者是否已刪除 |
| `sender_deleted_at` | `TIMESTAMPTZ` | `NULL` | 發送者刪除時間 |
| `receiver_deleted_at` | `TIMESTAMPTZ` | `NULL` | 接收者刪除時間 |
| `sent_at` | `TIMESTAMPTZ` | `NOT NULL`, `DEFAULT now()` | 訊息發送時間 |

#### 約束條件

```sql
-- 外鍵約束
FOREIGN KEY (conversation_id) REFERENCES public.conversations(id) ON DELETE CASCADE
FOREIGN KEY (sender_id) REFERENCES public.users(id) ON DELETE CASCADE
```

#### 資料表說明

- **訊息內容**: `content` 欄位儲存文字訊息內容,未來可擴展支援 JSON 格式以支援多媒體訊息
- **已讀狀態**: `is_read` 用於追蹤訊息是否被接收者閱讀
- **軟刪除支援**: 發送者和接收者可分別刪除訊息,互不影響
- **時間戳記**: `sent_at` 記錄訊息發送的精確時間,支援訊息排序

## 索引設計

### 🔑 索引列表

#### `conversations` 表索引

```sql
-- 1. 商品 ID 索引 (用於查詢特定商品的所有對話)
CREATE INDEX idx_conversations_item_id 
ON public.conversations(item_id);

-- 2. 買家 ID 索引 (用於查詢買家的所有對話)
CREATE INDEX idx_conversations_buyer_id 
ON public.conversations(buyer_id);

-- 3. 賣家 ID 索引 (用於查詢賣家的所有對話)
CREATE INDEX idx_conversations_seller_id 
ON public.conversations(seller_id);

-- 4. 複合索引:買家 + 更新時間 (優化買家對話列表查詢)
CREATE INDEX idx_conversations_buyer_updated 
ON public.conversations(buyer_id, updated_at DESC) 
WHERE NOT deleted_by_buyer;

-- 5. 複合索引:賣家 + 更新時間 (優化賣家對話列表查詢)
CREATE INDEX idx_conversations_seller_updated 
ON public.conversations(seller_id, updated_at DESC) 
WHERE NOT deleted_by_seller;
```

#### `conversation_messages` 表索引

```sql
-- 1. 對話 ID 索引 (用於查詢特定對話的所有訊息)
CREATE INDEX idx_conversation_messages_conversation_id 
ON public.conversation_messages(conversation_id);

-- 2. 發送時間索引 (用於訊息排序)
CREATE INDEX idx_conversation_messages_sent_at 
ON public.conversation_messages(sent_at DESC);

-- 3. 複合索引:對話 + 發送時間 (優化訊息列表查詢)
CREATE INDEX idx_conversation_messages_conversation_sent 
ON public.conversation_messages(conversation_id, sent_at DESC);

-- 4. 未讀訊息索引 (優化未讀訊息計數)
CREATE INDEX idx_conversation_messages_unread 
ON public.conversation_messages(conversation_id, is_read) 
WHERE NOT is_read;

-- 5. 發送者索引 (用於查詢用戶發送的訊息)
CREATE INDEX idx_conversation_messages_sender 
ON public.conversation_messages(sender_id);
```

### 📈 索引效益分析

1. **單欄位索引**: 支援基本的查詢需求
2. **複合索引**: 優化常見的查詢模式(如"查詢用戶的對話列表並按時間排序")
3. **部分索引**: 使用 `WHERE` 條件過濾,減少索引大小並提升查詢效能
4. **降序索引**: `DESC` 排序優化最新訊息/對話的查詢

## 觸發器機制

### 🔄 自動更新時間戳記

#### 1. `updated_at` 觸發器

自動更新 `conversations` 表的 `updated_at` 欄位。

```sql
-- 觸發器函數 (全局共用)
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 為 conversations 表建立觸發器
CREATE TRIGGER trigger_conversations_updated_at
    BEFORE UPDATE ON public.conversations
    FOR EACH ROW 
    EXECUTE FUNCTION update_updated_at_column();
```

**觸發時機**: 任何對 `conversations` 表的 UPDATE 操作

**用途**: 
- 追蹤對話的最後活動時間
- 用於對話列表排序
- 協助判斷對話的新鮮度

#### 2. 訊息觸發器 (可選擴展)

當新訊息插入時,自動更新對話的 `updated_at`:

```sql
CREATE OR REPLACE FUNCTION update_conversation_on_new_message()
RETURNS TRIGGER AS $$
BEGIN
    UPDATE public.conversations
    SET updated_at = NEW.sent_at
    WHERE id = NEW.conversation_id;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_update_conversation_on_message
    AFTER INSERT ON public.conversation_messages
    FOR EACH ROW 
    EXECUTE FUNCTION update_conversation_on_new_message();
```

## 安全性策略 (RLS)

### 🛡️ Row-Level Security 政策

#### `conversations` 表 RLS 政策

```sql
-- 啟用 RLS
ALTER TABLE public.conversations ENABLE ROW LEVEL SECURITY;

-- 政策 1: 用戶可以查看自己作為買家或賣家的對話
CREATE POLICY "Users can view their own conversations"
ON public.conversations
FOR SELECT
USING (
    auth.uid() = buyer_id OR auth.uid() = seller_id
);

-- 政策 2: 用戶可以插入自己作為買家的對話
CREATE POLICY "Users can create conversations as buyer"
ON public.conversations
FOR INSERT
WITH CHECK (
    auth.uid() = buyer_id
);

-- 政策 3: 用戶可以更新自己的對話 (軟刪除等)
CREATE POLICY "Users can update their own conversations"
ON public.conversations
FOR UPDATE
USING (
    auth.uid() = buyer_id OR auth.uid() = seller_id
)
WITH CHECK (
    auth.uid() = buyer_id OR auth.uid() = seller_id
);

-- 政策 4: 用戶可以刪除自己的對話
CREATE POLICY "Users can delete their own conversations"
ON public.conversations
FOR DELETE
USING (
    auth.uid() = buyer_id OR auth.uid() = seller_id
);
```

#### `conversation_messages` 表 RLS 政策

```sql
-- 啟用 RLS
ALTER TABLE public.conversation_messages ENABLE ROW LEVEL SECURITY;

-- 政策 1: 用戶可以查看所屬對話的訊息
CREATE POLICY "Users can view messages in their conversations"
ON public.conversation_messages
FOR SELECT
USING (
    EXISTS (
        SELECT 1 FROM public.conversations
        WHERE id = conversation_id
        AND (buyer_id = auth.uid() OR seller_id = auth.uid())
    )
);

-- 政策 2: 用戶可以在自己的對話中發送訊息
CREATE POLICY "Users can send messages in their conversations"
ON public.conversation_messages
FOR INSERT
WITH CHECK (
    sender_id = auth.uid()
    AND EXISTS (
        SELECT 1 FROM public.conversations
        WHERE id = conversation_id
        AND (buyer_id = auth.uid() OR seller_id = auth.uid())
    )
);

-- 政策 3: 用戶可以更新自己發送的訊息 (如標記已讀)
CREATE POLICY "Users can update their messages"
ON public.conversation_messages
FOR UPDATE
USING (
    EXISTS (
        SELECT 1 FROM public.conversations
        WHERE id = conversation_id
        AND (buyer_id = auth.uid() OR seller_id = auth.uid())
    )
);

-- 政策 4: 用戶可以刪除自己的訊息
CREATE POLICY "Users can delete their messages"
ON public.conversation_messages
FOR DELETE
USING (
    sender_id = auth.uid()
);
```

### 🔒 安全性特色

1. **身份驗證**: 所有操作都需要通過 `auth.uid()` 驗證用戶身份
2. **授權控制**: 用戶只能存取自己作為買家或賣家的對話
3. **資料隔離**: 透過 RLS 確保用戶無法查看他人的私密對話
4. **防止偽造**: 插入訊息時驗證發送者 ID 必須為當前用戶
5. **關聯檢查**: 使用 `EXISTS` 子查詢確保操作的對話確實屬於用戶

## 核心功能說明

### 1️⃣ 建立或取得對話

**功能**: 針對特定商品,自動建立或取得買賣雙方的對話室

**實作方式**: RPC 函數 `create_or_get_conversation(p_item_id)`

**邏輯流程**:
1. 驗證商品是否存在
2. 檢查當前用戶是否為商品擁有者(不能自己跟自己對話)
3. 查詢是否已存在對話室
   - 存在:返回現有對話
   - 不存在:建立新對話室

**特殊處理**:
- 使用 `ON CONFLICT DO NOTHING` 避免高併發時的重複插入
- 軟刪除的對話會被重新啟用

---

### 2️⃣ 查詢用戶對話列表

**功能**: 取得用戶所有對話,支援角色過濾與分頁

**實作方式**: RPC 函數 `get_user_conversations(p_page, p_size, p_role, p_include_deleted)`

**查詢邏輯**:
```sql
-- 依角色過濾
WHERE (
    (p_role = 'buyer' AND buyer_id = auth.uid()) OR
    (p_role = 'seller' AND seller_id = auth.uid()) OR
    (p_role IS NULL AND (buyer_id = auth.uid() OR seller_id = auth.uid()))
)

-- 過濾軟刪除 (可選)
AND (
    p_include_deleted OR
    (CASE 
        WHEN buyer_id = auth.uid() THEN NOT deleted_by_buyer
        WHEN seller_id = auth.uid() THEN NOT deleted_by_seller
    END)
)

-- 排序:最新對話在前
ORDER BY updated_at DESC

-- 分頁
LIMIT p_size OFFSET (p_page - 1) * p_size
```

**返回資料包含**:
- 對話基本資訊
- 商品資訊 (標題、圖片等)
- 對方用戶資訊 (暱稱、頭像)
- 最新訊息
- 未讀訊息數量

---

### 3️⃣ 查詢對話訊息

**功能**: 取得特定對話的所有訊息,支援分頁

**實作方式**: RPC 函數 `get_conversation_messages(p_conversation_id, p_page, p_size, p_include_deleted)`

**查詢邏輯**:
```sql
-- 驗證用戶有權限查看此對話
WHERE conversation_id = p_conversation_id
AND EXISTS (
    SELECT 1 FROM conversations
    WHERE id = p_conversation_id
    AND (buyer_id = auth.uid() OR seller_id = auth.uid())
)

-- 過濾軟刪除 (可選)
AND (
    p_include_deleted OR
    (CASE 
        WHEN sender_id = auth.uid() THEN NOT deleted_by_sender
        ELSE NOT deleted_by_receiver
    END)
)

-- 排序:最舊訊息在前
ORDER BY sent_at ASC

-- 分頁
LIMIT p_size OFFSET (p_page - 1) * p_size
```

---

### 4️⃣ 發送訊息

**功能**: 在對話室中發送新訊息

**實作方式**: RPC 函數 `send_message(p_conversation_id, p_content)`

**執行步驟**:
1. 驗證對話存在且用戶有權限
2. 插入新訊息記錄
3. 更新對話的 `updated_at` (透過觸發器自動完成)
4. 觸發 Realtime 事件通知接收者

**驗證邏輯**:
```sql
-- 確保用戶是對話參與者
WHERE id = p_conversation_id
AND (buyer_id = auth.uid() OR seller_id = auth.uid())
```

---

### 5️⃣ 標記訊息為已讀

**功能**: 將對話中的未讀訊息標記為已讀

**實作方式**: RPC 函數 `mark_messages_as_read(p_conversation_id)`

**更新邏輯**:
```sql
UPDATE conversation_messages
SET is_read = true
WHERE conversation_id = p_conversation_id
  AND sender_id != auth.uid()  -- 只標記對方發送的訊息
  AND NOT is_read              -- 只標記未讀訊息
```

**適用場景**:
- 用戶打開對話室時自動執行
- 批量標記已讀,提升效能

---

### 6️⃣ 查詢未讀訊息數量

**功能**: 取得用戶所有對話的未讀訊息總數

**實作方式**: RPC 函數 `get_unread_message_count()`

**查詢邏輯**:
```sql
SELECT COUNT(*)
FROM conversation_messages cm
JOIN conversations c ON cm.conversation_id = c.id
WHERE (c.buyer_id = auth.uid() OR c.seller_id = auth.uid())
  AND cm.sender_id != auth.uid()
  AND NOT cm.is_read
```

**用途**:
- 顯示應用程式的未讀訊息徽章
- 提醒用戶有新訊息

---

### 7️⃣ 軟刪除對話

**功能**: 用戶可以刪除對話,但不影響對方

**實作方式**: 更新 `deleted_by_buyer` 或 `deleted_by_seller` 欄位

**刪除邏輯**:
```sql
UPDATE conversations
SET 
    deleted_by_buyer = CASE WHEN buyer_id = auth.uid() THEN true ELSE deleted_by_buyer END,
    deleted_by_seller = CASE WHEN seller_id = auth.uid() THEN true ELSE deleted_by_seller END,
    buyer_deleted_at = CASE WHEN buyer_id = auth.uid() THEN now() ELSE buyer_deleted_at END,
    seller_deleted_at = CASE WHEN seller_id = auth.uid() THEN now() ELSE seller_deleted_at END
WHERE id = p_conversation_id
  AND (buyer_id = auth.uid() OR seller_id = auth.uid());
```

**特色**:
- 雙向獨立:買家和賣家可分別刪除,互不影響
- 保留記錄:資料庫中保留完整記錄,僅在查詢時過濾
- 可恢復:透過更新欄位為 `false` 即可恢復

## 效能優化

### ⚡ 查詢優化技巧

#### 1. 使用 CTE (Common Table Expressions)

避免重複計算,提升查詢可讀性:

```sql
WITH user_conversations AS (
    SELECT *
    FROM conversations
    WHERE buyer_id = auth.uid() OR seller_id = auth.uid()
),
latest_messages AS (
    SELECT DISTINCT ON (conversation_id)
        conversation_id,
        content,
        sent_at
    FROM conversation_messages
    WHERE conversation_id IN (SELECT id FROM user_conversations)
    ORDER BY conversation_id, sent_at DESC
)
SELECT 
    uc.*,
    lm.content AS latest_message,
    lm.sent_at AS latest_message_time
FROM user_conversations uc
LEFT JOIN latest_messages lm ON uc.id = lm.conversation_id
ORDER BY uc.updated_at DESC;
```

#### 2. 索引覆蓋查詢

確保常用查詢能夠使用索引:

```sql
-- 優化前:全表掃描
SELECT * FROM conversation_messages 
WHERE conversation_id = 123 
ORDER BY sent_at DESC;

-- 優化後:使用複合索引 idx_conversation_messages_conversation_sent
SELECT id, conversation_id, sender_id, content, sent_at
FROM conversation_messages 
WHERE conversation_id = 123 
ORDER BY sent_at DESC;
```

#### 3. 分頁查詢最佳實務

使用 OFFSET/LIMIT 進行分頁:

```sql
-- 第1頁:顯示最新的20筆對話
SELECT * FROM conversations
WHERE buyer_id = auth.uid() OR seller_id = auth.uid()
ORDER BY updated_at DESC
LIMIT 20 OFFSET 0;

-- 第2頁
LIMIT 20 OFFSET 20;
```

**注意事項**:
- `OFFSET` 值過大時效能會下降
- 對於大量資料,考慮使用游標分頁 (Cursor-based Pagination)

#### 4. 避免 N+1 查詢問題

使用 JOIN 一次性取得關聯資料:

```sql
-- ❌ 不佳:需要 N+1 次查詢
-- 1. 查詢對話列表
SELECT * FROM conversations WHERE buyer_id = auth.uid();
-- 2. 對每個對話查詢最新訊息 (N 次)
SELECT * FROM conversation_messages WHERE conversation_id = ? ORDER BY sent_at DESC LIMIT 1;

-- ✅ 良好:一次查詢完成
SELECT 
    c.*,
    (
        SELECT content 
        FROM conversation_messages 
        WHERE conversation_id = c.id 
        ORDER BY sent_at DESC 
        LIMIT 1
    ) AS latest_message
FROM conversations c
WHERE c.buyer_id = auth.uid();
```

### 📊 效能監控建議

#### 1. 監控慢查詢

-- 啟用慢查詢日誌

## 常見問題

### ❓ Q1: 如何防止用戶自己跟自己對話?

**A**: 在 `create_or_get_conversation` RPC 函數中驗證:

```sql
-- 檢查當前用戶是否為商品擁有者
IF v_seller_id = auth.uid() THEN
    RAISE EXCEPTION '無法與自己建立對話';
END IF;
```

### ❓ Q2: 高併發時如何避免重複對話?

**A**: 使用資料庫的唯一性約束 + `ON CONFLICT` 處理:

```sql
-- 唯一性約束
UNIQUE(item_id, buyer_id, seller_id)

-- 插入時處理衝突
INSERT INTO conversations (item_id, buyer_id, seller_id)
VALUES (p_item_id, auth.uid(), v_seller_id)
ON CONFLICT (item_id, buyer_id, seller_id) DO NOTHING;
```

### ❓ Q3: 軟刪除的對話如何恢復?

**A**: 更新刪除標記欄位:

```sql
UPDATE conversations
SET 
    deleted_by_buyer = false,
    buyer_deleted_at = NULL
WHERE id = conversation_id 
  AND buyer_id = auth.uid();
```

### ❓ Q4: 如何實現訊息搜尋功能?

**A**: 建立全文檢索索引:

```sql
-- 建立 GIN 索引支援全文檢索
CREATE INDEX idx_conversation_messages_content_fulltext
ON conversation_messages 
USING GIN (to_tsvector('english', content));

-- 搜尋訊息
SELECT *
FROM conversation_messages
WHERE to_tsvector('english', content) @@ to_tsquery('english', 'search_term')
  AND conversation_id IN (
      SELECT id FROM conversations
      WHERE buyer_id = auth.uid() OR seller_id = auth.uid()
  );
```

### ❓ Q5: 如何處理大量歷史訊息?

**A**: 實施資料分區 (Partitioning):

```sql
-- 按時間範圍分區 (需要 PostgreSQL 10+)
CREATE TABLE conversation_messages_2025_q1 PARTITION OF conversation_messages
FOR VALUES FROM ('2025-01-01') TO ('2025-04-01');

CREATE TABLE conversation_messages_2025_q2 PARTITION OF conversation_messages
FOR VALUES FROM ('2025-04-01') TO ('2025-07-01');
```

### ❓ Q6: 如何確保訊息發送順序?

**A**: 使用 `sent_at` 時間戳記與自動遞增 ID:

```sql
-- 查詢時同時排序
ORDER BY sent_at ASC, id ASC
```

### ❓ Q7: 如何實現訊息撤回功能?

**A**: 新增撤回欄位:

```sql
-- 擴展資料表結構
ALTER TABLE conversation_messages
ADD COLUMN is_recalled BOOLEAN DEFAULT false,
ADD COLUMN recalled_at TIMESTAMPTZ;

-- 撤回訊息 (僅發送者可撤回,且限時5分鐘內)
UPDATE conversation_messages
SET 
    is_recalled = true,
    recalled_at = now()
WHERE id = message_id
  AND sender_id = auth.uid()
  AND sent_at > now() - INTERVAL '5 minutes';
```
